## ⛔⛔ Landmines found TODAY. Each one cost real time.

**1. `--warmup-steps 500` is required on EVERY torchvision run, not just mosaic.**
The legacy 35-step warmup crashed `cv_cocoinit_fold0` at epoch 2 on **`aug=geo`** — the
augmentation that had survived 8/8 on the frozen split. That 8/8 was survivorship; move to a
542-image fold and it diverges. `cocovindr` survived the same schedule, so the failure is
**init-dependent** and you would have finished with 10 good runs and 5 holes in the baseline arm.

**2. Uploading `splits.json` silently disables label generation.** ⚠ THE EXPENSIVE ONE.
`splits.build_or_load()` returned early when the file existed and never reached
`convert.build_or_load()`, which writes the 799 YOLO label files. Every image then loaded with
**zero boxes**. This does not crash and does not trip the NaN guard — focal loss with no
positives is simply tiny. It reads as `loss=0.0336 → 0.0014, val mAP50=0.0000` and would run
the full 120 epochs to a complete, worthless `metrics.json`.
🔑 **A healthy run starts near `loss=1.1–1.5`. Anything under ~0.1 at epoch 1 has no targets.**
Fixed at source (splits.py now calls convert on the load path) **plus** a halt in
`tv_detect._assert_labels_present()`. Both verified against the exact failing condition.

**3. `splits.json` must be UPLOADED, never rebuilt — the rebuild is not deterministic.**
`_stratified_split` seeds its shuffle with `hash(sig)`, and Python randomises string hashing
per process: `hash('active') % 997` measured **186 / 201 / 516** on three consecutive runs of
the same machine. A rebuild deals a **different sealed test set**, so locally-sealed TB images
become training data remotely. `TB_REQUIRE_SPLITS=1` turns that into a halt — set it on every
remote run. (The negatives are safe: `list_images` sorts and the rng is fixed.)

**4. Kaggle nests uploaded folders.** You get `TBX11K/TBX11K` and
`yolo_experiments/yolo_experiments`. Don't trust the layout — locate files with `rglob` and
assemble the tree explicitly. Cell in `docs/kaggle_launch.md`.

**5. `retinanet_s0`'s directory is still a 2-epoch smoke run** (16 train images, mAP 0.0231,
dated 2026-08-01). Known and recorded at RESULTS.md:187; the real 0.739 survives only as
cached preds in `ap_compare_screen/preds/retinanet.json`. Not a new problem — don't "discover"
it again.

**6. `summary.txt` said "AP on 120 test positives" on every run ever written.** Hardcoded
string; the sealed set is 121, and a CV fold is 160. Label only — the AP itself was always
computed from real per-image data. Now derived from the screening block's denominator.

## ▶▶ K4 — the brief for the next conversation

**What it is:** `byolvindr` + `mosaic_mixup` + `--warmup-steps 500` + **kornia differentiable
preprocessing**, on Kaggle. Its control is **K3** (`retinanet_sc_byolvindr_mosaicmix_w500_s0`),
already running. **K4 must differ from K3 in exactly one thing: kornia.** Do not change
`--batch 8 --accum 2`, `--bn-recalib 50`, `--freeze-bn`, or the warmup.

**⚠ Kornia was cut twice before and the user has now approved it — do NOT re-litigate.** The
user's stated goal is report substance: *"I want to do kornia so that it still adds some
substance to the report. That we at least did it."* An implemented method with an honest null
result is legitimate content. What the next conversation must protect is the **formulation**,
not the decision.

**The formulation that survives review:**
> A differentiable **photometric** preprocessing front-end — a handful of scalar parameters
> (gamma, contrast, unsharp-mask strength) applied via kornia before the detector, trained
> **end-to-end on the TRAINING loss only**, clamped to sane ranges. No bilevel optimisation,
> no validation search.

Why this and not the standard formulation:
- **The 119-image TBX11K val already has one job: selecting `best.pt`.** Searching an
  augmentation policy against it spends that signal twice — `best.pt` selection stops being
  honest and there is no clean signal left to detect it. That, not compute, was always the
  blocker (AutoAugment/DADA/Faster-AA all search against a val signal). At σ≈0.010 on 119
  images the search would also mostly fit noise.
- **Photometric transforms don't move bounding boxes**, so there is no box-geometry maths to
  get wrong — a real implementation saving on a 2-day budget.
- It is literally the `ideas.md:104` idea ("the enhancement trains end-to-end with the
  detector rather than being fixed"), so it reads as a contribution, not a footnote.
- ⛔ **Do NOT put learnable aug on the BYOL stage.** BYOL's loss rewards invariance to
  augmentation, so minimising it w.r.t. the augmentation has a trivial degenerate optimum —
  the identity transform. It would need an adversarial (maximise) formulation, and this arm
  has already lost 8.8 h to a BYOL collapse.

**Expected outcome: a tie.** n=1 per cell, σ≈0.010, bar ±0.025 — a single K3/K4 pair cannot
establish an effect. The deliverable is *"we implemented learnable preprocessing and measured
it honestly"*, and the write-up must say so rather than reading a Δ of 0.01 as a win.

**Launch mechanics:** `docs/kaggle_launch.md` has the verified cells. The K4 dataset must
carry the **patched** `yolo_common/splits.py` and `yolo_common/tv_detect.py` — an older
version reproduces landmine #2 and K4 would look fine while training on nothing.
Check at launch: `L2-vs-COCO(weights) 134.320` (byolvindr; cocovindr is 77.983),
`warmup=500 optimizer steps`, and **epoch-1 loss ≈ 1.0–1.5**.
